# 第 4 關：三視角走查

前三關（build / 文案對定稿 / Playwright）是**決定性**的：不跑模型、結果可重現。
它們擋不住的只有一類錯——「每個零件都對，但組起來不是定稿的樣子」。
Part 2 跟工程師手刻版比對時，漏掉的四項全部屬於這類：

| 漏掉的 | 為什麼前三關擋不住 |
|---|---|
| 項目模式一開始就畫出人數／日期／時段 | 元素都在、文案都對，只是**出現時機**錯 |
| 沒做預約成功的 LINE 加好友 popup | 定稿裡是獨立 frame，不看 frame 清單就不會發現少了 |
| 沒做路由（網址不變） | 純畫面比對看不出來 |
| 訂金須知照工程師 demo 寫，不是定稿版本 | 文案「有一份」而且自洽，只是**抄錯來源** |

（前兩項現在已經有 Playwright 斷言擋著了，見 `tests/smoke.spec.mjs`。）

## 為什麼是三個視角，不是跑兩次

同一顆模型看同一組輸入，跑第二次會漏掉同樣的東西——失誤是相關的，換模型也一樣。
真正的獨立性來自**換輸入管道**：A 拿到的是結構化 JSON、B 拿到的是像素、C 拿到的是清單，
三者的失誤本質上不可能相關。

同樣重要的是**換 context**：走查員不能是刻這份 code 的那個 session，
它會複述自己的假設。一定要開乾淨的 subagent。

| 走查員 | 輸入管道 | 專抓 |
|---|---|---|
| **A｜結構** | Figma REST 節點樹（含 variant 名、`visible` 屬性）vs 實作 DOM | 顯示時機、階層、條件渲染 |
| **B｜視覺** | 定稿 PNG vs Playwright 截圖，逐頁逐 state | 破版、間距、色、RWD |
| **C｜盤點** | Figma frame 清單（**含 `Modal /`、`popup` 開頭**）vs 實作待辦 | 整塊漏做 |

三個各自獨立跑、互相看不到彼此的結論，最後合併去重。

## 成本分配

A/B/C 用 **Sonnet 5** 跑（量大、每頁每 state 都要掃），
三份報告合併後交給 **Opus 5 仲裁**：判斷哪些是真發現、哪些是誤報，
以及「有沒有哪個面向根本沒人查」。模型差異花在需要判斷力的那一步，不是重複勞動上。

## Prompt 範本

### A｜結構

> 你是設計稿走查員，只負責「顯示時機與結構」，不要看文案也不要看顏色。
> Ground truth 是 Figma（file `AQilb21aXkXybY5c1wDFq8`），用 MCP `get_metadata` / `get_design_context` 取節點樹。
> **每個 section 的第一張圖（`_Start` 或無後綴）定義初始狀態**，一定要單獨看那張，不要只看「已選好」的圖。
> 逐項回報：哪個元素在定稿的哪個 state 才出現、實作是否一致。
> 只回報你能指出具體節點與具體 DOM 的差異，不要臆測。

### B｜視覺

> 你是設計稿走查員，只負責版面與樣式，不要判斷邏輯。
> 對照 `../gallery_assets/`、`../modes_assets/` 的定稿 PNG 與 Playwright 截圖，逐頁逐 state 比。
> 回報間距／字級／色／RWD（斷點 760px，手機版 390）的差異，附上頁面與位置。
> 字級間距色碼一律以 Figma `get_design_context` 的實際值為準，不要目測。

### C｜盤點

> 你是完整度稽核員。列出 Figma 該範圍內的**所有** frame，
> **包含 `Modal /`、`popup` 開頭的狀態圖**，跟實作已完成清單逐一對照。
> 只回報「定稿有、實作沒有」與「實作有、定稿沒有」，不要評論品質。

### 仲裁

> 這是三份獨立走查報告。逐條判斷：真發現 / 誤報 / 資訊不足。
> 對每個真發現，判斷能不能寫成 DOM 斷言（能的話給出選擇器與期望狀態）。
> 最後回答一個問題：**有沒有哪個面向三份報告都沒查到？**

## 回收機制（這關的重點）

走查抓到的每一條，只要能機器化，就**回填成 `tests/smoke.spec.mjs` 的斷言**，
選擇器寫進 `verify.config.mjs`。

這樣第 3 關會越跑越厚、第 4 關越跑越薄——抓過一次的錯以後由機器擋。
跑兩輪模型不會累積任何東西，這個會。

## 鐵則

1. **ground truth 只有 Figma**。工程師的實作是第三方參考，不是定稿。
2. **spec 用 `get_design_context` 取實際值**，定稿 PNG 只用來取樣語意色與核對版面。
3. **盤點時 popup / modal 類的 frame 也要列進待辦**，它們不在「畫面」清單裡。
4. 走查員必須是乾淨 context 的 subagent，不能是刻這份 code 的 session。
